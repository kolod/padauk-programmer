# Contract: формат пакета прошивки (format version 1)

Пакет — це одиниця, яку клієнт формує з файлу прошивки і передає в програматор (`PKG_BEGIN` /
`PKG_DATA` / `PKG_COMMIT`), а програматор зберігає без змін у слоті flash. Усі поля little-endian.
CRC — CRC-32/ISO-HDLC (`zlib.crc32`).

```
offset          size          поле
0               128           Header
128             2·N           Words[N]           u16, слово i = адреса i пам'яті програм
128+2N          2·⌈N/16⌉      DefinedMask        біт i (LSB-first у межах байта) = 1 ⇔ Words[i] задано
128+2N+2⌈N/16⌉  4             package_crc32      CRC усіх попередніх байтів пакета
```

`package_size = 128 + 2·N + 2·⌈N/16⌉ + 4`.

## Header (128 байт)

| Off | Тип | Поле | Правила |
|---|---|---|---|
| 0 | `u8[4]` | `magic` | ASCII `"PDKP"` |
| 4 | `u16` | `format_version` | `1` |
| 6 | `u16` | `header_size` | `128` |
| 8 | `u32` | `package_size` | за формулою вище; ≤ `max_package_size` з `GET_INFO` |
| 12 | `u16` | `chip_id12` | 12-бітний ID мікросхеми з `LIST_CHIPS` |
| 14 | `u16` | `image_words` (N) | 1 … `code_words` мікросхеми |
| 16 | `u32` | `flags` | див. нижче; невідомі біти MUST бути 0 |
| 20 | `u16` | `fuse` | значення fuse, якщо `FUSE_PRESENT` |
| 22 | `u16` | `run_vdd_mV` | напруга для `RUN`; 0 → типова 5000 |
| 24 | `u8[16]` | `reserved` | MUST бути 0 (серійний номер — завжди випадковий, параметрів немає) |
| 40 | `u32` | `source_crc32` | CRC-32 вихідного файлу (для показу клієнтом) |
| 44 | `u32` | `created_unix` | час створення пакета клієнтом; 0 — невідомо |
| 48 | `char[16]` | `chip_name` | назва або варіант назви з `LIST_CHIPS`, NUL-доповнена; має відповідати `chip_id12` |
| 64 | `char[32]` | `name` | **ім'я пакета**: UTF-8, NUL-доповнене, непорожнє, без керівних символів (`< 0x20`); для списків і екрана; клієнт за замовчуванням бере ім'я вихідного файлу без розширення |
| 96 | `char[28]` | `label` | необов'язковий опис: UTF-8, NUL-доповнений |
| 124 | `u32` | `header_crc32` | CRC-32 байтів 0…123 |

### `flags`

| Біт | Ім'я | Значення |
|---|---|---|
| 0 | `FUSE_PRESENT` | записати `fuse` |
| 1 | `ALLOW_SECURITY_FUSE` | дозволити fuse з увімкненим захистом від читання |
| 2 | `SKIP_ERASE` | не стирати (FLASH) перед записом |
| 3 | `SKIP_BLANK_CHECK` | не перевіряти чистоту — **лише FLASH**; для OTP-мікросхеми → `PKG_OTP_BLANK_CHECK_REQUIRED` |
| 4 | `SKIP_VERIFY` | не верифікувати |
| 5 | — | зарезервовано, MUST бути 0 (калібрується кожна вставка; щоб не калібрувати — не ставити макрос) |
| 6 | `SECURE_FILL` | заповнити незадані слова NOP до службових областей |
| 7 | — | зарезервовано, MUST бути 0 (вставка серійного номера заповнюється завжди, коли вона є) |
| 8 | `CREATED_BY_COPY` | пакет створено операцією `COPY`; клієнт MUST NOT встановлювати |
| 9–31 | — | зарезервовано, MUST бути 0 |

Заповнювач калібрувальної вставки ніколи не записується в мікросхему як є: на його місці завжди
пишеться вимірювальний цикл, який після калібрування завершується (для OTP — один повний запис і
один перезапис вставки).

## Перевірки програматора

**У `PKG_BEGIN` (лише заголовок):**

| Перевірка | Помилка |
|---|---|
| `magic`, `format_version`, `header_size`, `header_crc32`, зарезервовані біти | `PKG_HEADER_INVALID` |
| `name` порожнє, некоректний UTF-8 чи керівні символи; некоректний UTF-8 у `label` | `PKG_HEADER_INVALID` |
| `package_size` відповідає N і ≤ ємності слота | `PKG_TOO_LARGE` / `PKG_HEADER_INVALID` |
| `chip_id12` + `chip_name` є в таблиці | `PKG_CHIP_UNSUPPORTED` |
| мікросхема підтримує запис | `PKG_CHIP_READ_ONLY` |
| `N` ≤ `code_words` | `PKG_TOO_LARGE` |
| fuse із захистом без `ALLOW_SECURITY_FUSE` | `PKG_SECURITY_NOT_ALLOWED` |
| `SKIP_BLANK_CHECK` для OTP-мікросхеми (конституція, принцип III) | `PKG_OTP_BLANK_CHECK_REQUIRED` |

**У `PKG_COMMIT` (весь пакет, прочитаний назад із flash):**

| Перевірка | Помилка (+ `addr`) |
|---|---|
| `package_crc32` збігається | `PKG_CRC_MISMATCH` |
| задані слова не потрапляють у службові області мікросхеми | `PKG_RESERVED_AREA` |
| задане останнє слово (fuse) не суперечить `FUSE_PRESENT`/`fuse` | `PKG_FUSE_CONFLICT` |
| fuse з образу із захистом без `ALLOW_SECURITY_FUSE` | `PKG_SECURITY_NOT_ALLOWED` |
| усі вставки калібрування розпізнано | `PKG_CALIB_UNKNOWN` |
| не більше 16 вставок калібрування (`addr` — 17-а) | `BAD_PAYLOAD` |

Біти слова вище розрядності ядра мікросхеми ігноруються.

## Ефективний образ (що реально записується)

Програматор обчислює його на льоту з пакета:

1. задані слова; незадані — «не записувати» (усі одиниці), або NOP, якщо `SECURE_FILL`;
2. останнє слово пам'яті виключається з основного запису й пишеться як fuse останнім кроком;
3. вставки калібрування замінюються вимірювальним циклом, після калібрування — на `MOV A,#k` + NOP;
4. вставки серійного номера отримують байти нового випадкового 64-бітного номера (молодший — першим).

## Пакети, створені `COPY`

Програматор сам формує пакет із дампу еталона (`chip_name`; `name` — з `ext` команди `COPY` або `"copy <chip_name> <crc>"`,
де `<crc>` — 8 hex-цифр `image_crc_norm` еталона; `label` порожній; fuse з
останнього слова; серійний номер еталона, якщо він є, **не розпізнається** й переноситься як є — FR-052). Сліди калібрування (research R9) замінюються стандартними
вставками free-pdk:

- IHRC/ILRC: `'R','C', kind, freq[0..3], mV[0..1], reg` з визначеною ціллю;
- BandGap: `'B','G', 3, 3950 & 0xFF, 3950 >> 8, bgtr, gpcc, gpcs, 0 × 6` з адресами з таблиці мікросхеми.

**Внутрішнє значення частоти `0xFF0000kk`** у вставці IHRC/ILRC означає «ціль невідома: при `PROGRAM`
виміряти копію зі значенням регістра `kk`, округлити до стандартної SYSCLK (`SNAP_STANDARD`); якщо
відхилення > 10 % — записати `kk` без калібрування». Таке значення неможливе у вставці з реальної
програми (> 4 ГГц), тому програматор приймає його лише в пакетах із прапорцем `CREATED_BY_COPY`
(біт 8), який встановлює тільки сам програматор; пакет із PC з цим бітом → `PKG_HEADER_INVALID`.

## Еталонні значення

Приклад: PFS154 (`chip_id12 = 0x0AA1`), образ із 3 слів, без fuse:
`N = 3`, `DefinedMask` = 2 байти `07 00`, `package_size = 128 + 6 + 2 + 4 = 140`.
Тестові вектори пакетів зберігаються в `software/tests/vectors/` і використовуються і прошивкою, і клієнтом.
